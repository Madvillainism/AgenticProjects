1. ARQUITECTURA GENERAL
═══════════════════════════════════════════════════════════════

DeskDog es una mascota de escritorio que corre como ventana
PyQt6 transparente y siempre al frente. Tiene dos capas:

  Backend (Python 3.10+)
  ┌─────────────────────────────────────────────────────┐
  │  PyQt6 QMainWindow (frameless, transparent)         │
  │  ├── QWebEngineView (carga frontend/dist/index.html)│
  │  ├── DeskDogBridge (IPC vía QWebChannel)            │
  │  └── PatrolController (timer + animación de posición)│
  └─────────────────────────────────────────────────────┘

  Frontend (TypeScript + Vite)
  ┌─────────────────────────────────────────────────────┐
  │  Renderizado dentro del QWebEngineView              │
  │  ├── PetRenderer (estados idle/walking/sleeping)    │
  │  ├── SpeechBubble (mensajes aleatorios)             │
  │  ├── ProfileSelector (elección inicial)             │
  │  └── bridge-client.ts (comunicación con Python)     │
  └─────────────────────────────────────────────────────┘

La comunicación entre capas usa QWebChannel — un protocolo
JSON sobre el transporte interno de Qt WebEngine. No hay
HTTP, WebSockets, ni archivos intermedios (salvo config.txt).

Archivo: main.py

── 2.1 Configuración de ventana ──────────────────────────────

La ventana es cuadrada de 150×150px y completamente

── 2.2 Carga del frontend ────────────────────────────────────

  if getattr(sys, "frozen", False) and hasattr(sys, "_MEIPASS"):
      base = sys._MEIPASS       # Modo PyInstaller
  else:
      base = os.path.dirname(...)  # Modo desarrollo

  index_path = os.path.join(base, "frontend/dist/index.html")
  self.view.setUrl(QUrl.fromLocalFile(index_path))

La lógica de "frozen" permite que funcione tanto en

── 2.3 Bridge + Channel ──────────────────────────────────────

  channel = QWebChannel()
  channel.registerObject("bridge", self.bridge)
  self.view.page().setWebChannel(channel)

El objeto "bridge" queda disponible en JS con el mismo
nombre. Los métodos anotados con @pyqtSlot son llamables.

── 2.4 Zona de clic (TransparentForInput) ────────────────────

  SPRITE_ZONE_W = 44
  SPRITE_ZONE_H = 44

  def mouseMoveEvent(self, event):
      sprite_zone = QRect(
          (self.width() - SPRITE_ZONE_W) // 2,
          (self.height() - SPRITE_ZONE_H) // 2,
          SPRITE_ZONE_W, SPRITE_ZONE_H,
      )
      if sprite_zone.contains(event.position().toPoint()):
          # Activar clics
          self.setAttribute(WA_TransparentForMouseEvents, False)
      else:
          # Clics pasan a través
          self.setAttribute(WA_TransparentForMouseEvents, True)

Solo los 44×44px centrales de la ventana reciben clics.
El resto de la ventana es click-through.

── 2.5 Arranque diferido ─────────────────────────────────────

  self.patrol_controller = PatrolController(self, animate=True)
  self.bridge.setStartAppCallback(self._start_services)

  def _start_services(self):
      self.patrol_controller.start()

El patrol NO arranca al crear la ventana. Espera a que
el frontend llame bridge.startApp() (después de adoptar).

── 2.6 Cierre ─────────────────────────────────────────────────

  def closeEvent(self, event):
      self.patrol_controller.stop()
      super().closeEvent(event)

Al cerrar, frena el timer y animación de patrol.

4. patrol.py — FÍSICA DE PATRULLAJE ALEATORIO
═══════════════════════════════════════════════════════════════

Archivo: patrol.py

Mueve la ventana a coordenadas aleatorias cada cierto tiempo.

── 4.1 Constantes ────────────────────────────────────────────

  VIEWPORT_W = 120
  VIEWPORT_H = 120
  PATROL_INTERVAL = 12000       # 12 segundos entre movimientos
  PATROL_ANIM_DURATION = 4000   # 4 segundos de animación

VIEWPORT_W/H es el margen de seguridad contra bordes:
la ventana nunca se posiciona a menos de 120px del borde
(detectado con screeninfo o QGuiApplication).

── 4.2 PatrolController ──────────────────────────────────────

  def _move_random(self):
      1. Obtener dimensiones del monitor
      2. Calcular max_x = ancho_monitor - VIEWPORT_W
      3. Elegir new_x, new_y aleatorios
      4. Si animate=True:
         - Crear QPropertyAnimation sobre la propiedad "pos"
         - StartValue: posición actual
         - EndValue: new_x, new_y
         - Duration: PATROL_ANIM_DURATION (4000ms)
         - Easing: InOutCubic (acelera/desacelera suave)
         - Emitir patrolMoving(true)
      5. Si animate=False: mover instantáneo

── 4.3 Easing ─────────────────────────────────────────────────

  self._animation.setEasingCurve(QEasingCurve.Type.InOutCubic)

InOutCubic produce un movimiento que arranca despacio,
acelera a mitad de camino y vuelve a减速 al final.
Se siente más natural que el lineal.

  2. Se guarda petType y petName en config.txt
  3. Se crea PetRenderer con el nombre

  5. Se llama bridge.startApp() (arranca patrol)

── 6.3 Menú contextual ───────────────────────────────────────

      e.preventDefault();

Cerrar llama bridge.closeApp(). Al hacer clic fuera se cierra.

── 6.4 Estado de sueño ───────────────────────────────────────

  document.addEventListener("mousemove", resetSleepTimer);

  function resetSleepTimer() {
      if (asleep) {
          asleep = false;
          renderer.setState("idle");  // Despertar al primer move
      }
      clearTimeout(sleepTimer);
      sleepTimer = setTimeout(() => {
          asleep = true;
          renderer.setState("sleeping");
      }, 10000);  // 10 segundos sin mouse
  }

El timer de 10s se resetea con cada mousemove. Si pasan
10s sin movimiento → sleeping. El primer movimiento después
de dormir despierta al sprite inmediatamente.

── 6.5 Mensajes periódicos ───────────────────────────────────

  let messageInterval = 600000;  // 10 minutos default
  const config = JSON.parse(await bridge.loadConfig());
  if (config.messageInterval) messageInterval = Number(...)

      if (bubble.isVisible()) return;
      const msg = getRandomMessage();
      bubble.show(msg.body, msg.actions);
  }, messageInterval);

Cada messageInterval ms, muestra un mensaje aleatorio del
JSON. No muestra otro si ya hay uno visible. messageInterval
es configurable desde config.txt.

10. frontend/src/bridge-client.ts — CLIENTE QWebChannel
═══════════════════════════════════════════════════════════════

Archivo: frontend/src/bridge-client.ts

Implementación mínima del protocolo QWebChannel en TypeScript.

── 10.1 initBridge ───────────────────────────────────────────

  export function initBridge(): Promise<any> {
      return new Promise((resolve, reject) => {
          if (!window.qt?.webChannelTransport) {
              reject(new Error("QWebChannel transport not available"));
              return;
          }
          new QWebChannel(window.qt.webChannelTransport, (channel) => {
              bridgeRef = channel.objects.bridge;
              resolve(bridgeRef);
          });
      });
  }

Detecta si hay Qt disponible. Si no (ej: en navegador web),
devuelve error. Si sí, inicia el canal y expone bridge.

── 10.2 QWebChannel class ────────────────────────────────────

  - init: envía {id: 0, type: "init"} y registra objetos
  - exec: despacha mensajes type "init", "signal",
    "propertyUpdate", "response"
  - Cada método @pyqtSlot se convierte en una función
    que devuelve Promise (envía {id, type: "call", ...})
  - .connect(signalName, callback) escucha señales de Qt

── 10.3 getBridge ────────────────────────────────────────────

  export function getBridge(): any {
      return bridgeRef;
  }

Devuelve la referencia al bridge ya iniciado (o null).

13. config.txt — CONFIGURACIÓN PERSISTENTE
═══════════════════════════════════════════════════════════════

Archivo: config.txt (en la raíz del proyecto)

Formato: key=value (una por línea)
Comentarios: líneas que empiezan con #

Keys actuales:
  petType         = dog | cat

  messageInterval = número en ms (default: 600000)

Ejemplo:
  petType=dog
  petName=Firulais

y _write_txt() en bridge.py.

Diferencia con JSON: no requiere comillas, no hay riesgo
de sintaxis inválida por coma faltante.

14. scripts/slice_sprites.py — GENERACIÓN DE SPRITES
═══════════════════════════════════════════════════════════════

Archivo: scripts/slice_sprites.py

Extrae frames individuales de sprite sheets JPG fuente
y los compone en nuevas tiras PNG horizontales con altura
objetivo.

Uso:
  python scripts/slice_sprites.py TARGET_HEIGHT=44

Parámetros:
  TARGET_HEIGHT=44 → cada frame se redimensiona a 44px
  de alto (manteniendo aspect ratio).

  Si TARGET_HEIGHT no se pasa, usa 52 como default.

Proceso:
  1. Lee imágenes JPG de source_dog/ y source_cat/
  2. Cada imagen es un sprite sheet con frames iguales
  3. Corta cada frame, lo redimensiona a TARGET_HEIGHT
  4. Compone todos los frames en una tira PNG horizontal
  5. Guarda en frontend/public/sprites/

Nomenclatura:
  {pet}-{state}.png
  Ej: dog-idle.png, dog-walking.png, cat-sleeping.png

15. FLUJO DE INICIO COMPLETO
═══════════════════════════════════════════════════════════════

Paso a paso desde que se ejecuta DeskDog.exe:

 1. PyQt6 crea DeskDogWindow (150x150, transparente,
    frameless, siempre al frente)

 2. Carga frontend/dist/index.html en QWebEngineView

 3. main.ts ejecuta initBridge():
    - Detecta window.qt.webChannelTransport
    - Crea QWebChannel, envía init handshake
    - Python responde con objetos (bridge)
    - bridgeRef queda listo

 4. main.ts crea ProfileSelector(bridge):
    - Muestra overlay con tarjetas Perro/Gato + input nombre
    - Llama bridge.loadConfig() para preseleccionar si hay
      datos guardados

 5. Usuario elige tipo, escribe nombre, clic "Adoptar"

 6. ProfileSelector destruye overlay

 7. main.ts guarda: bridge.saveConfig("petType", "dog")
    bridge.saveConfig("petName", "Firulais")

 8. main.ts crea PetRenderer("dog"):
    - Crea divs .pet-name y .sprite.dog-idle en #app
    - renderer.setName("Firulais")

 9. main.ts crea SpeechBubble()

10. main.ts conecta señal:
      bridge.connect("patrolMoving", (moving) => {
          renderer.setState(moving ? "walking" : "idle");
      })

11. main.ts llama bridge.startApp()
     → Python arranca patrol_controller.start()
     → PatrolController mueve la ventana aleatoriamente
       cada 12s con animación de 4s

12. main.ts configura sleep timer:
      - Cada mousemove resetea timer de 10s
      - Sin mouse por 10s → sprite pasa a sleeping
      - Primer mouse después de dormir → vuelve a idle

13. main.ts inicia setInterval de mensajes:
      - Cada messageInterval ms (default 10 min)
      - Elige mensaje aleatorio de messages.json
      - Muestra bubble si no hay otra visible
      - Todos los botones solo dismiss

14. Clic derecho en sprite → menú contextual:
      - "Cerrar" → bridge.closeApp() → cierra todo
      - "Cancelar" → cierra menú
